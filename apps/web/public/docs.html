A friendly guide

Keep words, sketches, and teamwork in one place.

SquillPad is a browser-based spatial notebook for Markdown notes, handwritten ink, diagrams, images, and live collaboration. This guide gets you from a fresh checkout to useful everyday workflows.

The short version

One computer runs the SquillPad host and keeps the notebook folder. You open the notebook in a browser on that computer or on another device. The host saves the work and, when sharing is enabled, sends page updates to connected browsers.

1. StartRun the host on the computer that stores your notebook.
2. ConnectOpen the authorized link in a recent browser.
3. MakeType, draw, organize, and share as you work.

Good news: a client device does not need the repository, Node.js, or a separate SquillPad install. It only needs a browser and the host's connection link.

Host, client, and notebook: the simple picture

It helps to think of SquillPad as one notebook with two ways to look at it. The host is the computer holding the notebook. A client is any browser window using that notebook.

Host device = the home for the notebook

  • Runs the launcher and keeps the project folder on its local disk.
  • Owns canonical saves, sharing controls, profiles, and GitHub snapshots.
  • Needs Node.js, pnpm, and the SquillPad repository.
  • Must stay running for other devices to connect and collaborate live.

Client device = a browser window

  • Opens the authorized URL from the host; no project folder is copied over.
  • Can be a laptop, tablet, phone, or another computer on the same network.
  • Can type, draw, and move around the notebook while sharing is enabled.
  • Can keep local edits during a short network outage and sync them after reconnecting.

If the host is deliberately stopped, connected clients become read-only until the host is started again. They can still browse, pan, zoom, and use the laser pointer.

Install and start SquillPad

SquillPad currently runs from this repository. It does not include a separate desktop installer. From the repository root, you need:

  • Node.js 22.12 or newer. CI uses Node.js 24.20.0.
  • pnpm 11. The repository uses pnpm 11.25.0.
  • A recent Chromium, Firefox, or Safari/WebKit browser.

  1. Install the workspace dependencies once.

    pnpm install

  2. Create a notebook project and its launcher. This example creates a project outside the checkout, uses port 4173, builds SquillPad, and writes a launcher called personal-notes.sh. 

    ./scripts/create-new-project.sh \
  --name "Personal Notes" \
  --directory "$PWD/../squillpad-notes" \
  --port 4173

  3. Run the launcher. Keep the terminal open while you use the notebook. The launcher starts the host and opens its authorized URL in your default browser. 

    ./launchers/personal-notes.sh

If the browser does not open automatically, use the authorized URL printed by the launcher. The project folder must be empty or absent when you create a new project. The folder stays on disk after you stop the host, so use the same launcher next time.

Create your first notebook

  1. Choose a home. The directory passed to the project script is your notebook folder. Pick a place you can find again and back up.

  2. Add structure only when you need it. Use New section and New page in the navigation panels. Rename a section or page by clicking its title, then drag items to reorder them.

  3. Put different kinds of thinking together. Choose Text for Markdown, Pen for handwriting, Shapes for lines and diagrams, or paste a supported image onto the canvas.

  4. Return whenever you like. Start the same launcher and reconnect in a browser. Pages, drawings, Markdown, and images remain in the project folder.

For a backup or move, copy the whole notebook folder. A single page file is not enough to preserve the complete notebook and its images.

Use a host and a client on different devices

The host and client are not two copies of the application. The host computer keeps the notebook; the second device simply opens it in a browser. Only the host needs the repository and the command line.

  1. Start on the host device. Run the project's launcher. LAN sharing is enabled by default. Open Sharing in the top bar to see the current state, the connection link, and the option to show a QR code.

    If your computer has a firewall, allow the chosen port on your trusted local network only. Do not forward the port to the public internet.

  2. Give the client device the link. Put both devices on the same trusted Wi-Fi or wired network. On the host, choose Show QR code and scan it, or copy the complete authorized client URL.

  3. Connect from the client device. If the connection screen appears, paste the full authorized URL, including the access token, and choose Connect. On the first visit, create a profile with a username and password. On later visits, sign in with that profile; you normally do not need a new access link.

  4. Check the page status. Open the same page on both devices. When the header says Synchronized, Markdown, ink, shapes, and page changes appear on the other device without a reload. Presence avatars show the profiles that are currently active in the project.

  5. Choose the right collaboration view. Live editing is page-scoped, so people can work on different pages at the same time. To keep an eye on another page while editing your own, use the Picture in picture workflow below. On one page, agree on different canvas regions when two people want to work side by side.

Sharing controls on the host

  • LAN sharing: turn live remote editing on or off.
  • Start with LAN sharing by default: choose what the next host start should do.
  • Maximum clients: set the number of client slots, including the host. The setting resets to its default when the host restarts.

When the connection changes

  • Offline — editing locally: keep working; the browser will synchronize again after reconnecting.
  • Sharing disabled: the host can still edit locally, while remote clients become read-only after they reload.
  • Host stopped: restart the same launcher to bring live editing back.

LAN sharing uses unencrypted HTTP, including password login. Use a trusted network. Treat the authorized URL like a powerful key: it can create, reset, or remove profiles. Stopping the host revokes its links, but a browser that already connected may still have an offline copy.

Where SquillPad can save real time

SquillPad is most useful when a task is too visual for a plain document but too fluid for a rigid project tool. Keep the rough thinking and the finished explanation together, then share or export the part that is ready.

Meetings that end with a usable plan

Keep an agenda and action list in Markdown, sketch the decision or system map beside it, and let a second person capture notes live. After the meeting, export the page as Markdown instead of rewriting the notes from scratch.

Project planning without losing the messy ideas

Use sections for Inbox, This week, and Decisions. Put rough arrows and boxes next to the written plan, move groups of objects together, and duplicate a useful page as the next planning session's starting point.

Research and study with fewer tabs

Import Markdown, paste images, write a derivation by hand, and keep code or math next to the explanation. Search all Markdown on the page, then use a live reference view while writing a summary in another part of the notebook.

Teaching, pairing, and design review

One person can explain with ink and a laser pointer while another types examples or marks questions. Presence shows who is there, and a shared page keeps the review focused on the same visual material.

Visual briefs and handoffs

Combine a short brief, screenshots, wireframe shapes, and annotations on one canvas. Group and copy the useful pieces, then export an editable SVG for a diagram workflow or a PNG for a quick message or slide.

A second screen for focused work

Keep a checklist, reference diagram, or worked example visible in Picture in picture while you draft on a different page. Fullscreen gives the main canvas room; the small view keeps context nearby without another application window.

Cross-device capture

Leave the host on a laptop or home computer and use a tablet with a stylus as the writing surface. Use the phone for a quick look, or continue locally during a short Wi-Fi interruption and let the host catch up later.

Long-running personal knowledge

Keep durable notes, diagrams, formulas, and decisions in human-readable project files. Named Markdown styles, custom drawing palettes, page backgrounds, search, backups, and optional GitHub snapshots make the notebook easier to return to months later.

Small workflows with a big payoff

These are deliberately narrow recipes. Try one exactly as written, then adapt it to the way you think.

Two collaborators, two pages, two live views

  1. Both people connect to the same host. Person A opens Plan; person B opens Research.

  2. Each person briefly opens the other page, chooses Miscellaneous tools → Picture in picture, and draws a rectangle around the region to watch.

  3. Each person returns to their own page. The small reference view stays visible and updates live while the main canvas remains available for editing.

  4. Use the main canvas to edit. Picture-in-picture is read-only, so it is safe to keep a plan, source page, or review area in view. Move or resize the view when it gets in the way.

Two collaborators, one page, separate regions

  1. Agree on a simple boundary, such as notes on the left and a diagram on the right.

  2. One person uses Text for decisions and action items while the other uses Pen, Highlight, or Shapes.

  3. Use the Laser tool to point at the exact item being discussed without adding permanent marks.

  4. When the page is ready, export the written part as Markdown or the visual part as SVG/PNG.

Tablet drafting with a stylus

  1. On the tablet, open Settings and turn on Touch input lock. This is useful when the tablet does not have reliable palm rejection.

  2. Enter fullscreen. Finger touches on the canvas are now blocked so a resting palm cannot pan the page or leave an accidental mark. The stylus still works normally for writing, drawing, and selecting.

  3. If you need to move around, press and hold the patterned circle in the bottom right. While holding it, use a finger to pan or zoom; release it when you are done so touch is locked again.

  4. Turn on the Radial toolbar toggle in the fullscreen canvas toolbar. With the stylus, press and hold anywhere on the canvas to open the quick tool ring at that spot, then choose Pen, Highlight, Erase, Text, Laser, or a color without reaching for the toolbar.

Meeting notes to handoff

  1. Make one page with an agenda, a free area for sketches, and an action list.

  2. During the meeting, type decisions into Markdown and draw arrows or boxes around the important relationships.

  3. Use Select to move the final action list near the top and duplicate the page if it becomes a reusable meeting template.

  4. Open the Page menu and choose Export page Markdown when the written follow-up is ready.

Source material to explanation

  1. Choose Page → Import Markdown or paste a supported image into a research page.

  2. Put handwritten calculations, highlights, and arrows beside the source instead of opening a separate annotation tool.

  3. Use Search Markdown to jump between terms, then create a second page for the clean explanation.

  4. Keep the source page in Picture in picture while you write the explanation, then export the finished page.

Draft a paper without managing a pile of boxes

  1. Create one Markdown box for the opening paragraph, edit it, and choose Create text box group in the editor.

  2. Choose Add text box below to make the next part. Use separate boxes for an equation, a second paragraph, a short code example, or a heading.

  3. Keep the architectural diagram as a Shapes drawing or pasted image beside the relevant text. The canvas stays open for visual material while the text group keeps the written sequence together.

  4. Move the group by dragging its top-left group handle, not one of the text boxes. Copy it when you need a similar section, and export the page as Markdown when the prose is ready to share.

Work through a short network outage

  1. Watch the status in the header. Offline — editing locally means the browser is keeping your changes locally.

  2. Continue writing or drawing. Avoid clearing the browser's site data while those edits are waiting.

  3. Return to the trusted network or bring the host back, then wait for Synchronized.

  4. Check the page after reconnecting. The browser and host merge the offline work into the shared page.

Review a project on another host

  1. Use LAN sharing for live work nearby. Use GitHub snapshots when two host computers need the same project at different times.

  2. On the first host, choose Sync now to publish a reviewed local snapshot.

  3. On the second host, choose Previous snapshots or Sync now and inspect the side-by-side pages before applying anything.

  4. If both hosts changed, choose Combine both changes or make one snapshot the complete winner after reviewing it.

Everyday use

  • Organize sections and pages: drag items to reorder them. Use a three-dot menu or right-click to add below, copy and paste, duplicate, move, or delete. A copied section or page includes its notes, drawings, and images. Deleting asks for confirmation.
  • Customize navigation: use a section's action menu to choose its bookmark color. Drag the divider beside either navigation panel to resize it, or focus the divider and use the arrow keys. Use the panels toggle when you want more room for the canvas.
  • Write Markdown: choose Text, click the canvas, and type. Double-click or tap a Markdown box to edit its source. The editor supports GitHub-flavored Markdown, links, tables, checklists, mathematics, and highlighted code. Drag a box to move it, resize it from an edge or corner, and use Settings to change rendered font size or box opacity. For a longer piece of writing, turn related boxes into a Markdown text box group.
  • Search your writing: use the Search Markdown field in the toolbar. Press Enter for the next match and Shift+Enter for the previous match. Press Escape to clear the search.
  • Draw: use Pen for ink and Highlight for a translucent marker stroke. Custom palettes give each of six slots its own color, thickness, and opacity. When Pen or Highlight is set to Custom, press a color slot once to select it, then press the selected slot again to edit the current slot's color, thickness, and opacity. Profile palette settings can follow a signed-in profile across devices.
  • Make diagrams: choose Shapes, then Line, Arrow, Rectangle, or Ellipse. Turn on Fill when a shape needs a colored interior. Select objects to change their color, thickness, opacity, order, or grouping.
  • Use images: paste supported PNG, JPEG, GIF, or WebP images onto the canvas. Images are stored with the page and travel with the project folder.
  • Select and move: tap an object to select it or drag across blank canvas to lasso ink, shapes, images, and Markdown boxes. Use two fingers to pan or zoom on a touch device. Use Group/Ungroup when several objects should move together.
  • Reuse work: copy and paste selected objects, or duplicate a selection with Ctrl/Cmd+D. Markdown source, grouped text boxes, and pasted images stay together when copied inside SquillPad.
  • Erase: remove a whole stroke or touched shape, or choose Segment to erase only part of an ink stroke.
  • Make room: open Miscellaneous tools, choose Insert space, and drag a horizontal cut down to move crossing and lower objects. Drag it up to remove extra space.
  • Point without leaving a mark: choose Laser and drag. The fading pointer is visible to page collaborators and disappears on its own.
  • Move around: choose Hand, or hold Space while dragging. On a phone or tablet, the toolbar scrolls horizontally so the controls remain reachable.

A finished pen stroke is left alone when you choose the next pen color. To change an old stroke, choose Select first, click the stroke, and then choose its new color.

Build a flowing draft with Markdown text box groups

A Markdown text box group is a stack of Markdown boxes that behaves like one piece of writing on the canvas. It is made for content that is too rich for one small label but still belongs together: a paragraph, an equation, another paragraph, and a diagram or image nearby. SquillPad keeps the text boxes in order and opens space as the stack grows, so you can concentrate on the draft instead of arranging every box by hand.

How to make one

  1. Choose Text, click the canvas, and write a non-empty Markdown box. Double-click it or tap it to open the editor.

  2. Choose Create text box group. The first box becomes the beginning of the group.

  3. In that editor, choose Add text box below. A fresh Markdown box is placed below the current one and opens for editing. Repeat this for each paragraph, equation, list, heading, or code block that belongs in the draft.

  4. Choose Select, then drag the group's top-left handle—not one of the text boxes—to move the whole written stack. Copying or duplicating the group keeps its Markdown boxes together. If one box no longer belongs, edit it and choose Detach; its content remains on the page as a separate Markdown box.

A natural research-paper layout

Put the introduction paragraph in the first box, the displayed equation in the next, and the explanation in a third. Add a fourth box for a result or transition. Then place an architectural diagram beside the passage with Shapes or a pasted image. The writing remains a clean, editable sequence while the diagram can sit exactly where the reader needs it. When the page is ready, Export page Markdown combines the Markdown boxes in reading order for a draft you can continue elsewhere.

The group controls appear in the Markdown editor. Create text box group starts a group; Add text box below extends it; Detach removes only the current box from the group. These actions do not flatten your Markdown into one hard-to-edit block.

Fullscreen and Picture in picture

Use the fullscreen button at the end of the canvas toolbar when you want the page to fill the screen. Press Escape to leave fullscreen. In fullscreen, turn on the Radial toolbar toggle in the canvas toolbar for quick access to common tools from the canvas itself.

Keep another page in view

  1. Open the page you want to watch. Choose Miscellaneous tools, then Picture in picture.

  2. Drag a region around the part of the page you want to keep visible.

  3. Navigate to another page. The reference window stays on screen and updates from its source page in real time.

  4. Drag the window itself to move it. To resize it, hover over the window until the resize indicator appears in the bottom-right corner, then drag that corner. The aspect ratio stays locked.

  5. To close the window, press and hold the PiP window. An X appears in its top-right corner; press the X to close it. You can keep more than one reference view open.

A Picture-in-picture window is a live, read-only view. Edit the source page from its main canvas or close the reference before trying to change its content.

Bring things in and take things out

The Page menu in the canvas toolbar contains import and export actions. Pick an export region before exporting an image or SVG:

  • Import Markdown: choose a .md or text file and place its contents on the page.
  • Export page Markdown: turn the page's Markdown boxes into one Markdown document in reading order.
  • Content bounds: include all content on the page.
  • Visible viewport: export the part currently inside the canvas window.
  • Selected objects: export only the objects selected with Select. This option becomes available after you make a selection.
  • Export SVG: save the selected region as editable vector artwork.
  • Export PNG: save the selected region as a shareable image.

Make the notebook fit you

Open Settings in the top bar for preferences that make long sessions and different devices more comfortable.

  • Page background: choose Blank, Ruled, or Grid.
  • Readable text: adjust Markdown box opacity, rendered Markdown font size, and the overall app text scale.
  • Touch and stylus work: choose whether pen input draws while touch navigates. Turn on Touch input lock when you want fullscreen touch to be blocked while stylus input continues to work; hold the patterned bottom-right button when you need to pan or zoom with a finger.
  • Drawing comfort: set laser trace decay, arrow-key panning speed, and the canvas toolbar height.
  • Autosave: when LAN sharing is disabled, a host can choose how often pending changes are saved. You can also use the Save control in the header.
  • Profile settings: signed-in profiles can carry drawing palettes across devices. Settings also offer Export profile and Import profile; these transfer settings only, never passwords, sessions, or access tokens.
  • Project settings: hosts can use Export project and Import project to transfer notebook-wide preferences such as default zoom, Markdown appearance and named styles, ink colors, laser decay, LAN-sharing defaults, and autosave frequency. Project, section, and page names and content are not included. Imported Markdown styles are merged with existing styles.
  • Named Markdown styles: press Text; the Edit styles button appears in the toolbar. Use it to create or edit a style. To apply one, select a Markdown text box and set Color style at the bottom left to the style you want.

GitHub snapshots: keep separate hosts in step

GitHub snapshots are useful when the same SquillPad project needs to move between two host computers—for example, a desktop at home and a laptop at work—or when you want a history you can inspect before changing the current notebook. The host stores a canonical project snapshot in a dedicated GitHub repository, then another host can fetch and review it.

This is separate from LAN collaboration. LAN sharing is the live connection for nearby browsers using one host. GitHub is a snapshot shelf between hosts; it is not a live collaboration server and is not needed for ordinary local editing.

Set it up

  1. Prepare the host. Git must be available on the host. Configure Git author information and an SSH key or agent outside SquillPad. Create or choose a dedicated GitHub repository that is empty or already contains a valid SquillPad project at its root. SquillPad requires the SSH remote format git@github.com:owner/repository.git; HTTPS remotes are not supported because the web app cannot prompt for GitHub usernames or passwords.

  2. Open the host-only Sync control. Choose the circular-arrow Sync button in the top bar. Connected clients do not see this control. Enter the GitHub SSH repository URL git@github.com:owner/repository.git and, if useful, an optional first snapshot note.

  3. Choose Connect and inspect. SquillPad checks the repository and links it to this host. An empty repository receives the first local snapshot. If the remote already has a project, SquillPad opens a review when the two snapshots differ.

  4. Repeat on another host when needed. Run SquillPad there with its own local project folder, connect it to the same dedicated repository, and review the GitHub snapshot before applying it. For a predictable handoff, let one host finish its sync before the other host publishes new work.

SquillPad does not collect or persist GitHub tokens. The remote repository must not be treated as a live notebook connection. Use LAN sharing when people need to edit together in real time.

What happens when you choose Sync now

SquillPad first flushes pending notebook changes, may make a local snapshot, fetches the configured GitHub branch, and compares the two sides. If the local side is newer, it can publish it. If GitHub is newer, it opens a read-only review. If both sides changed, it opens a conflict review instead of silently replacing one side.

What each button does

The screen may show different buttons depending on whether the repository is new, up to date, ahead on one side, or in conflict. Here is the complete tour.

Compare snapshots Shows the selected older and newer pages side by side. Turn it off to preview one side at a time.

Use local snapshot for GitHub contents Publishes the reviewed local project as the GitHub version. Use it only after checking what remote work it replaces.

The change bars labeled Publish local and Apply remote estimate additions and removals. Treat whole-snapshot choices as consequential: review the side-by-side pages first, especially when both hosts have been edited.

If something goes wrong

Most problems are about which host is running, which project folder it opened, or whether the connection link is complete. Start with the question that sounds closest to what you see.

What should I do after the SquillPad repository changes?

Stop the old host with Ctrl+C. From the repository root, install dependencies if the package files changed, rebuild the application, and regenerate the launcher with the same project name, folder, and port. The old launcher contains the recreate command in its comments. 

pnpm install  # when dependencies or the lockfile changed
pnpm build
./scripts/create-new-project.sh \
  --launcher-only --replace-launcher \
  --name "Personal Notes" \
  --directory "$PWD/../squillpad-notes" \
  --port 4173
./launchers/personal-notes.sh

This makes the launcher use the rebuilt browser and host files and keeps its recorded project path and port current. If you moved the project, use the new directory in the launcher command.

The host will not start. What should I check?

Confirm that Node.js is at least 22.12 and pnpm 11 is available in the terminal. Run pnpm install from the repository root if dependencies are missing, then run pnpm build. Check that the launcher still points to a real project folder containing notebook.json.

The browser cannot connect to the host.

Make sure the launcher terminal is still open, sharing is enabled, and both devices are on the same trusted network. Paste the complete authorized URL, including the access token. A client device cannot use a host-only localhost URL; use the network URL printed by the launcher or shown in Sharing. A firewall may also need to allow the chosen port on the local network.

The QR code or link does not work.

Open Sharing on the host and show a fresh QR code. Check that the client is on the same network, then try copying the complete link into the connection screen instead. Do not remove the part after the #; it carries the access token.

I connected, but the client is read-only.

The host may have disabled LAN sharing, lost its connection, or been stopped. On the host, turn LAN sharing back on and reload the client. If the host was stopped, run the same launcher again. A stopped host leaves clients able to browse but not edit.

My collaborator cannot see an edit.

Check that both people opened the same page and that the header says Synchronized. Collaboration updates are page-scoped. If one person is looking at a different page, use Picture in picture to keep that page visible and live. A Picture-in-picture view is read-only, so edit from the main canvas.

The status says “Offline — editing locally.”

Keep working if you are comfortable doing so. The browser is holding the edits locally. Restore the network or restart the host, keep the notebook tab open, and wait for Synchronized. Avoid clearing the browser's site data while offline edits are waiting. If the host was deliberately stopped, the page is read-only instead; restart the host first.

Changes are waiting to be saved or the Save control shows an error.

Check that you are on the host and that its terminal is still running. If LAN sharing is disabled, the host uses the autosave frequency in Settings and can also save the current page with the header's Save control. Click it again after checking the error message. Keep a copy of the project folder before investigating unusual storage problems.

I cannot find my notebook or a page looks empty.

Start the host with the same project folder used when the notebook was created. Check the selected section and page; SquillPad stores pages separately. If you moved the project, copy the entire folder and regenerate the launcher with --launcher-only --replace-launcher and the new directory.

GitHub synchronization stopped or shows a review.

Git must be installed on the host, Git author information must be set, and an SSH key or agent must work outside SquillPad. Check that the remote uses the form git@github.com:owner/repository.git, is dedicated to SquillPad, and is empty or has a valid SquillPad project at its root. If both the host and GitHub changed, use the review rather than starting a second sync. SquillPad does not intentionally overwrite remote history when an operation stops; correct the problem and try again.

The snapshot review changed while I was looking at it.

Another sync may have changed the local or GitHub snapshot. Close or finish the old review, choose Sync now or Refresh, and reopen the review from the new comparison. Do not rely on an old review after either side has moved on.

I want to recover an older GitHub version.

Open Previous snapshots, choose the older and newer sides, inspect the read-only preview, then choose Restore older snapshot… or Restore newer snapshot…. Confirm only after checking the listed paths. Restore creates a new snapshot, so the old history remains available.

Is it safe to use LAN sharing on public Wi-Fi?

No. LAN transport uses unencrypted HTTP and is intended for a trusted network. Do not expose the host port to the public internet or an untrusted network. Treat the authorized link as sensitive, and remember that a browser may retain an offline copy even after an account is removed.

Good to know

  • A Node.js host process must remain running to serve the browser client and own canonical project saves.
  • There is no standalone browser-only or packaged desktop mode in this repository.
  • Stylus pressure is not captured or saved; strokes use fixed-width styles.
  • SquillPad is primarily a personal project, so development and support may be intermittent.
